# 작업 기록 앱 시연 시나리오

_마지막 갱신: 2026-11-23 · 발표 자료: 같은 폴더의 `작업 기록 앱-(대인배)-발표.pptx` (본편 10장 + 숨긴 부록 5장), 발표 대본은 [작업 기록 앱 발표 대본.md](작업%20기록%20앱%20발표%20대본.md), 시연 대본은 [작업 기록 앱 시연 대본.md](작업%20기록%20앱%20시연%20대본.md) · 앱 0.3.0 기준(탭: 대시보드 · 타임라인 · 보고서 · 검색 · 설정)_

이 문서는 시연 준비와 장면별로 누를 것, 비상 대처를 다룹니다. 시연 중에 할 말은 [시연 대본](작업%20기록%20앱%20시연%20대본.md)에 따로 있습니다.

## 개요

발표와 시연을 합쳐 **15분**입니다(질문 제외). 슬라이드 1–10번(마지막 장 감사합니다까지)을 6분 동안 발표하고, 슬라이드 쇼를 마치고 앱 화면으로 넘어가 6분 5초 시연한 뒤, **앱 화면을 띄운 채로** 질문을 받습니다.

시연은 **브라우저 탭 하나**에서 위쪽 메뉴(대시보드 · 타임라인 · 보고서 · 검색 · 설정)만 바꿔 가며 합니다. 발표 자료와 앱을 Alt+Tab으로 오가지 않고, 탭도 바꾸지 않습니다.

시연은 **데모 모드**(`--demo`)로 합니다. 평소 DB와 따로 만들어 둔 데모 DB `demo-1116.db`에 개발자 한 명의 가상 한 주(**2026-11-16(월)–11-20(금)**, 작업 폴더 `gov24-minwon-api`, `poc-k8s`, `업무 문서`와 그 파일 변경 포함)를 넣어 띄우고, 화면 위에 "데모 데이터입니다" 띠가 나옵니다. 평소 기록이 화면에 나올 걱정이 없습니다.

데모 모드는 **새로 기록하지 않습니다**(창 기록, 작업 폴더 확인 모두 꺼짐). 그래서 지금 파일을 고쳐 바로 기록되는 장면은 없고, 데모 데이터에는 가릴 비밀번호가 없어서 `***`로 가려지는 모습도 보여 줄 수 없습니다. 가리기는 말로 설명합니다.

- **AI 결과는 되도록 미리 만들어 둡니다.** 주간보고 초안과 기록에 있는 질문의 답을 발표 전에 같은 탭에서 받아 둡니다. 다른 메뉴에 갔다 와도 그대로 남습니다. 물어보기 답은 한 번에 하나만 남으므로, 기록에 없는 질문만 그 자리에서 묻습니다(Claude로 10–20초).
- 앱 화면은 발표 슬라이드에 넣지 않고 시연에서만 보여 줍니다(같은 화면이 두 번 나오지 않게). 시연 화면 캡처는 숨긴 부록 11–13번에 두었습니다.
- 기본으로 장면 3을 빼고 장면 7은 마무리 대사만 남깁니다. 시간이 남으면 장면 7 전체(+45초) → 장면 3(+40초) 순서로 되살리고(둘 다 되살려도 14:30), 모자라면 장면 5 → 장면 1의 숫자 설명 순서로 줄입니다. 장면 2, 4, 6은 끝까지 남깁니다.

## 사전 준비

1–2는 **발표 전날**(리허설), 3–5는 **당일 시작 30분 전**에 합니다.

### 1. 데모 띄우기 (전날 리허설, 당일)

데모 데이터는 날짜를 **2026-11-16(월)–11-20(금)**으로 고정한 데모 DB `%LOCALAPPDATA%\WorkHistory\demo-1116.db`를 씁니다.
이 DB는 저장소의 `tools/demo_week.py`로 만듭니다(어느 PC에서 만들어도 같은 내용).
그냥 `--demo`로 켜면 그날 기준으로 날짜가 바뀐 `demo.db`가 열리므로, 꼭 `--db`로 이 파일을 지정합니다.
AI 모델은 이 DB에 Claude Code · Sonnet으로 미리 맞춰 두었습니다.

1. `demo-1116.db`가 없으면 저장소 폴더에서 만듭니다. 이미 있으면 덮어쓰지 않고 멈춥니다.
   ```
   .venv\Scripts\python.exe tools\demo_week.py
   ```
   배포 zip에는 tools 폴더가 없으므로, 저장소에서 만든 파일을 옮겨 씁니다.
2. 켜져 있는 데모 앱이 있으면 끕니다(평소 앱은 켜 둬도 됩니다. 데모는 다른 포트로 뜹니다).
3. 리허설 전에 `demo-1116.db`와 `demo-1116-snapshots` 폴더를 다른 곳에 복사해 둡니다(잘못 만졌을 때 되돌리기용).
4. 저장소 폴더에서 명령 프롬프트(cmd)를 열고 실행합니다. Claude 데스크톱 앱 안이 아니라 일반 명령 프롬프트에서 실행합니다(그 안에서는 데이터 폴더가 따로 잡힐 수 있음).
   ```
   start-workhistory.cmd --demo --db "%LOCALAPPDATA%\WorkHistory\demo-1116.db"
   ```
   배포 zip이면 `작업 기록.cmd`에 같은 인수를 붙입니다.
5. 브라우저에 앱이 열리고 위에 "데모 데이터입니다" 띠가 나오는지 봅니다. 주소의 포트(`5730`이 쓰이고 있으면 `5731` 등)를 적어 둡니다.
   데모는 마지막 기록일(11-20)로 열리고, 보고서도 그 주(11-16 – 11-22)로 열립니다.

데모 데이터의 줄거리 (대본의 ○○를 채울 때 씁니다):

- 토큰 재발급 버그 **GOV-1418**: 재현·원인 분석(월) → `TokenRefreshFilter` 수정, MR !312(화) → QA 확인 완료로 종료(목)
- K8s 전환 PoC(`poc-k8s`): dev 클러스터에 민원 API 배포 성공, ingress 설정은 아직(수)
- 민원 조회 지연 **GOV-1423** 시작: 응답 3.2초, 복합 인덱스로 0.4초까지 단축, DBA 검토 요청 필요(목–금)
- 파일이 바뀐 날: 월·화·금 `gov24-minwon-api` 3개씩(금은 `업무 문서` 1개 더), 수 `poc-k8s` 2개, 목 없음

다른 PC에서 시연하면 그 PC에서 1번으로 새로 만들거나, `demo-1116.db`와 `demo-1116-snapshots`를 함께 같은 폴더에 옮겨 씁니다.

### 2. 화면 점검과 AI 결과 확인 (전날 리허설)

| 화면 | 확인할 것 |
| --- | --- |
| 대시보드 주 · 11-16 – 11-22 (장면 1) | 고친 파일 12개, 한 일에 `gov24-minwon-api`, `poc-k8s`가 나옴 |
| 대시보드 한 일 → `gov24-minwon-api` 줄 (장면 1) | 열린 창에 날짜 목록이 나오고, 날짜를 누르면 그날 타임라인으로 감 |
| 타임라인 앱별 (장면 2에 쓸 날: 11-16(월) 또는 11-17(화)) | 앱 카드와 창 제목이 나옴. 경로가 나오는 창을 하나 골라 둠 |
| 결과물 변경에서 파일을 누름 (장면 2) | 바뀐 줄(빨간 줄·초록 줄)이 짧고 알아보기 쉬운 파일을 하나 골라 둠 |
| 보고서 주간보고 · 11-16 – 11-22 (장면 4) | AI 초안이 나오고, 오른쪽 출처에 주황색(파일 변경) 출처가 있음. 누를 출처를 골라 둠 |
| 보고서 주간보고 초안 → 보낼 내용 보기 (장면 5) | 초안이 그대로 있고, 그 아래에 보낼 내용이 펼쳐짐 |
| 검색 (장면 3) | 검색어 `GOV-1418`로 세션과 변경 파일이 나옴 |

AI 준비:

1. 설정 탭 → **AI 설정**에서 Claude Code · Sonnet이 골라져 있는지 보고 **연결 확인**을 누릅니다.
    - 이 PC에 Claude Code가 설치되어 있고 로그인된 상태여야 합니다. 연결 확인이 실패하면 리허설 전에 해결합니다.
    - 데모 모드는 지어낸 데이터라 AI로 보내는 데 따로 동의를 묻지 않습니다.
2. 물어보기 질문 두 개를 돌려 보고 답과 걸린 시간을 적어 둡니다. [시연 대본](작업%20기록%20앱%20시연%20대본.md) 장면 6의 ○○ 부분은 이 답에 맞춰 채웁니다.
    - 기록에 있는 일: "GOV-1418 토큰 재발급 오류는 어디까지 했지?"
    - 기록에 없는 일: "AI 기본법 대응 작업은 어디까지 했지?"(부록 13번과 같은 질문)

### 3. 브라우저 탭 하나 준비 (당일 30분 전, 1을 마친 뒤)

데모 앱 주소를 **탭 하나**로 열고, 아래 순서대로 해 둡니다. 순서가 중요합니다.

1. **보고서** 메뉴 → **주간보고** → 11-16 – 11-22 주인지 확인 → **AI 초안 만들기**. 초안과 오른쪽 출처가 나오면 장면 4에서 누를 주황색 출처를 골라 둡니다.
2. **검색** 메뉴 → **AI에게 묻기**에 기록에 있는 질문("GOV-1418 토큰 재발급 오류는 어디까지 했지?") → **묻기**. 답이 나오면 그대로 둡니다.
3. **타임라인** 메뉴 → 보기를 **앱별**로 바꿉니다.
4. **대시보드** 메뉴 → **주** (11-16 – 11-22). 이 화면으로 시연을 시작합니다.

주의할 것:

- 보고서 초안은 **저장을 누르지 마세요.** 저장하면 본문은 남지만, 다시 열 때 오른쪽 출처 칸이 비어 나옵니다.
- 보고서에서 **업무일지로 바꾸거나 주를 옮기지 마세요.** 초안이 사라집니다. 다른 메뉴(대시보드, 타임라인, 검색, 설정)에 갔다 오는 것은 괜찮습니다.
- **AI에게 묻기**를 다시 누르면 앞의 답이 사라집니다. 발표 전에는 1번 질문 뒤로 아무것도 묻지 않습니다.
- **새로 고침(F5)하지 마세요.** 초안과 답이 화면에서 사라집니다.

### 4. 화면과 발표 환경

- 브라우저 확대를 125–150%로 올리고(Ctrl + +), F11 전체 화면으로 둡니다.
- 발표자 보기를 쓰면, 브라우저 창을 미리 **청중이 보는 화면** 쪽으로 옮겨 둡니다. 화상회의라면 화면 전체를 공유해야 브라우저로 넘어갔을 때도 보입니다.
- 메신저, 메일 등 다른 창을 닫고 Windows의 방해 금지 모드를 켭니다.
- 노트북은 전원을 연결합니다.

## 장면별 동작

### 장면 1 · 대시보드 (1분)

1. 발표 자료 마지막 장 "감사합니다"에서 인사를 마친 뒤 슬라이드 쇼를 끝냄
2. 앱 화면(대시보드, 주 · 11-16 – 11-22)을 띄움 → 위쪽 "데모 데이터입니다" 띠를 가리킴
3. 위쪽 네 숫자(활동 시간, 업무 비율, 고친 파일, 가장 많이 쓴 앱)를 차례로 가리킴
4. **분류별 시간** 막대(요일별)를 가리킴
5. **한 일**과 **작업 폴더별 결과물**을 가리킴
6. **한 일**의 `gov24-minwon-api` 줄을 누름 → 열린 창의 날짜 목록에서 장면 2에 쓸 날을 누름 → 그날 타임라인으로 넘어감

- 3–5번은 가리키기만 합니다. 6번에서 열린 창의 날짜를 누르면 창이 닫히고 타임라인으로 바로 갑니다.
- 활동 시간 아래의 "지난주 같은 기간보다" 비교는 데모 데이터에 그 전 주가 없어 "비교할 기록 없음"으로 나옵니다. 말하지 않습니다.

### 장면 2 · 하루 기록 (1분 15초)

1. 앱 카드 하나를 가리킴: 앱마다 하루 쓴 시간을 합치고, 창 제목별 시간이 안에 나옴
2. 미리 고른 창 줄 하나를 누름 → 나오는 경로(파일 경로나 웹 주소)를 가리킴
3. 오른쪽 **결과물 변경**에서 미리 고른 파일 하나를 누름 → 빨간 줄과 초록 줄을 가리킴
4. **닫기**

- 타임라인 보기가 앱별이 아니면 **앱별**을 누릅니다(사전 준비 3에서 맞춰 둔 것이 그대로 남습니다).
- 시간을 아끼려고 세션을 고치거나 병합하지 않고 가리키기만 합니다.

### 장면 3 · 검색 (40초 · 기본은 뺌)

1. **검색** 메뉴 → `GOV-1418`을 넣고 **검색**
2. 결과의 **작업 세션**과 **변경 파일** 묶음을 가리킴
3. 결과 하나의 날짜를 누름 → 그날 타임라인으로 옮겨진 것을 가리킴

- 검색 메뉴의 위쪽 **AI에게 묻기**가 아니라 아래쪽 검색 칸을 씁니다. AI에게 묻기를 누르면 미리 받아 둔 답이 사라집니다.

### 장면 4 · 주간보고 (1분 30초)

1. 위쪽 **보고서** 메뉴 → 미리 만든 11-16 – 11-22 초안이 나옴
2. 왼쪽 초안을 위에서 아래로 천천히 훑음 → 업무 묶음 이름(이슈 번호, 저장소) 하나를 가리킴
3. "(근거 없음)", "(AI 제안 — 확인 필요)", "(완료 근거 없음 — 확인 필요)" 표시가 있으면 가리킴
4. 오른쪽 출처 칸에서 미리 고른 주황색 "파일 변경" 출처를 누름 → 열린 변경 내용을 가리킴
5. **닫기** → 위쪽 **보고서** 메뉴로 초안에 돌아옴

- 3번의 표시가 하나도 없으면 다음 계획 줄의 "AI 제안"만 가리킵니다.

### 장면 5 · 보낼 내용 보기 (30초)

1. 같은 주간보고 화면에서 **AI 초안 만들기** 옆의 **보낼 내용 보기**를 누름 → 초안 아래에 펼쳐진 보낼 내용의 위쪽 몇 줄만 가리킴

- **AI 초안 만들기**는 누르지 않습니다. 누르면 초안을 다시 만듭니다.

- 보낼 내용은 길어서 스크롤하며 읽지 않습니다. 데모 데이터에는 비밀번호가 없어 `***`는 나오지 않으므로, 가리기는 말로만 설명합니다.

### 장면 6 · 물어보기 (1분 15초)

1. 위쪽 **검색** 메뉴 → 미리 받아 둔 답과 출처를 따라 가리킴, 답 아래 "확인한 기록: 기록 검색 → 하루 보기…" 줄을 가리킴
2. **AI에게 묻기** 칸의 질문을 지우고 "AI 기본법 대응 작업은 어디까지 했지?"를 넣고 **묻기**
3. 기다리는 동안 대본의 설명을 이어 감 → "찾지 못했습니다" 답이 나오면 가리킴

- 리허설에서 이 질문이 걸린 시간을 재 둡니다. 30초가 넘어도 안 나오면 "기록에 없는 일은 이렇게 찾지 못했다고 답합니다"라고 말로 정리하고 넘어갑니다.

### 장면 7 · 기록 통제와 마무리 (1분 20초 · 기본은 6번만, 35초)

1. 위쪽 **일시정지** 버튼을 가리킴 (누르지 않음)
2. **설정** 메뉴 → **기록 대상**을 가리킴
3. **제외 목록**을 가리킴
4. **AI 설정**을 가리킴
5. **데이터 삭제**를 가리킴
6. 앱 화면을 그대로 둔 채 마무리 대사를 하고 질문을 받음

- 설정은 가리키기만 하고 바꾸지 않습니다.
- 질문에 부록(설치, 도구와 AI 등)이 꼭 필요할 때만 발표 자료로 돌아갑니다.

## 비상 대처

장면 하나에서 문제가 생기면 그 장면만 건너뛰고 다음 장면으로 갑니다. 앱 자체가 안 되면 슬라이드 쇼에서 숨긴 부록 11–13번(시연 화면 캡처)을 띄워 설명하고(번호를 누르고 Enter), 마지막 장(10번)으로 가서 질문을 받습니다. 남는 시간은 질문으로 채웁니다.

| 상황 | 대처 |
| --- | --- |
| 앱이 열리지 않거나 화면 공유가 안 됨 | 부록 11–13번(실제 앱 화면 캡처)을 띄워 "실제 앱 화면입니다"라고 설명한 뒤 질문을 받음 |
| 데모 띠가 없음 (평소 앱이 열림) | 주소의 포트가 데모 앱 것인지 확인. 평소 기록이 보이면 주소창에서 데모 앱의 포트로 바꿈 |
| 대시보드 날짜가 11-16 – 11-22가 아님 | **주** → ◀/▶로 맞춤. 고친 파일이 0개면 다른 주이거나 `demo-1116.db`가 아닌 `demo.db`가 열린 것이니 설정에 나오는 DB 경로를 확인 |
| 한 일 줄을 눌렀는데 날짜 목록이 안 나옴 | 창을 닫고 **타임라인** 메뉴 → 날짜를 직접 골라 장면 2로 감 |
| 새로 고침 등으로 초안이나 답이 사라짐 | 보고서의 **작성** → **AI 초안 만들기**나 **묻기**를 다시 누름(Claude로 10–20초). 30초 안에 안 나오면 그 장면을 건너뜀 |
| 발표 전에 AI 초안이 끝내 안 나옴 | 연결 확인으로 Claude 로그인 상태를 봄. 안 되면 장면 4·6을 빼고 그 시간은 질문으로 채움 |
| 출처를 눌렀는데 엉뚱한 화면이 나옴 | 위쪽 **보고서** 메뉴로 돌아와 다음 장면으로 넘어감 |
| AI 답이 전날과 다름 | 화면에 나온 답을 그대로 설명하고, 출처가 붙어 있다는 점만 강조함 |
| 시간이 모자람 | 장면 5 → 장면 1의 숫자 설명 순서로 줄임 (장면 3은 기본으로 빠져 있고 장면 7은 마무리 대사만). 장면 2, 4, 6은 남김 |
| 시간이 남음 | 질문을 일찍 받음. 시연을 늘리지 않음 |
| 시연 중에 질문이 나옴 | "시연 끝나고 바로 답하겠습니다"라고 하고 이어 감 |

리허설은 적어도 한 번, 발표할 PC에서 실제로 해 봅니다.
