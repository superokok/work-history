# 프로젝트 구조 한눈에 보기

새 세션에서 가장 먼저 읽는 문서. 상세 설계는 [ARCHITECTURE.md](ARCHITECTURE.md)를 본다.
구조가 바뀌면 이 문서를 함께 고친다.

_마지막 갱신: 2026-11-10_

## 무엇인가

**작업 기록 (WorkHistory)**: 개발자용 로컬 전용 업무 기록 앱.

- 주 기록 = **결과물**: 등록한 작업 폴더의 파일 변경을 5분마다 숨김 Git 저장소(dulwich)에 스냅샷.
- 보조 기록 = **창 활동**: 앱이 직접 기록한 앱/창 제목/유휴 상태를 작업 폴더별 하루 기록으로 모음.
- 화면은 탭 5개: 대시보드(첫 화면), 타임라인, 보고서(AI), 검색(+"AI에게 묻기"), 설정(작업 폴더·실행·AI·개인정보).
- AI 보고서·"AI에게 묻기"는 내 PC AI (llama.cpp + Qwen3.5, 인터넷 불필요).
  Claude Code는 개발 환경에서만 쓰는 비교용 선택지이며 배포본에는 없다.
- 배포: GitHub Releases에 행망용 앱 zip(`-offline`, Claude Code 연결 제외) + AI 모델 조각 + `WorkHistory-setup.cmd`.
  setup을 더블클릭하면 앱을 풀고 모델을 합쳐 넣고 실행 → 창 없이 실행, 설정은 모두 앱 안에서.
- 스택: Python 3.11+ (표준 라이브러리 위주) + 바닐라 HTML/JS, SQLite. 빌드 단계 없음. **Windows 전용.**
- 저장소: GitHub (비공개), 브랜치 `main`.
- 라이선스: 자체 코드는 PROPRIETARY. 의존성은 상업적 판매 가능한 것만.

## 자주 쓰는 명령

```bash
# 개발 환경
uv venv .venv --python 3.12
uv pip install --python .venv/Scripts/python.exe -e .[claude] pip   # pip: 빌드 스크립트가 씀 (배포본에는 안 들어감)

# 실행 (기본 http://127.0.0.1:5730/, 막혀 있으면 5731~5739)
.venv/Scripts/python.exe -m workhistory            # 콘솔에 로그. start-workhistory.cmd는 pythonw(창 없음, 로그는 데이터 폴더 workhistory.log)
.venv/Scripts/python.exe -m workhistory --demo     # 데모 데이터 (별도 demo.db)
seed-demo.cmd                                      # 시연: 실제 앱 DB를 데모 데이터로 (기존 DB는 %LOCALAPPDATA%\WorkHistory\backup\)

# 테스트 (2026-11-13 기준 235개)
.venv/Scripts/python.exe -m unittest discover -s tests -t .

# AI 보고서 품질 평가 (기본: llm/의 가장 큰 로컬 모델. Claude Code 기준값은 --model claude-code:sonnet, 로그인 필요)
.venv/Scripts/python.exe -m evals.report_eval

# Windows 포터블 zip
python tools/build_portable.py --offline       # 행망용 앱 zip (Claude Code 연결 제외, llm/bin 포함·모델 제외, 약 45MB) = 배포본
python tools/release_parts.py dist/WorkHistory-<버전>-windows-x64-offline.zip
                                               # → dist/release: 앱 zip + llm/models의 모델 1.9GB 조각 + WorkHistory-setup.cmd
gh release create v<버전> dist/release/*        # 릴리스 (올리기 전에 사용자 확인)
python tools/build_portable.py --offline --with-models  # 모델까지 든 zip 하나 (-offline-local-ai) — 배포하지 않음, 직접 전달용
python tools/build_portable.py                 # 인터넷용(Claude Code 포함, 모델 제외) — 배포하지 않음, 개발 확인용

# 로컬 모델로 품질 평가 (기기 고정: WORKHISTORY_LLM_DEVICE=none 은 CPU만)
.venv/Scripts/python.exe -m evals.report_eval --model local:Qwen3.5-4B-Q4_K_M
```

데이터 폴더: `%LOCALAPPDATA%\WorkHistory`.

주의 (Windows, Claude 데스크톱 앱): Claude 안에서 띄운 프로세스는 `%LOCALAPPDATA%`가
`%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Local`로 가상화되어 **실제 앱과 다른 DB**를 본다.
실제 앱 데이터는 실행 중인 앱의 API(`http://127.0.0.1:5730/api/...`)로 확인·변경한다.
실제 앱은 Claude 밖에서 띄운다 (`explorer.exe "<시작프로그램>\작업 기록.lnk"`).

## 주요 결정 (바꾸기 전에 사용자에게 확인)

- 스택: Python 표준 라이브러리 + 바닐라 JS, 프레임워크 없음.
- 주 기록은 창 시간이 아니라 **파일 변경(결과물)**.
- 파일 변경의 프로젝트는 앱이 추측해서 넣지 않는다: 하위 폴더별로 추천하고 사람이 확인한 것만 쓴다 (2026-10-28).
- 스냅샷은 dulwich(Apache-2.0)로, git.exe·GPL 의존 금지.
- **Windows 전용**, 창 기록은 앱의 내장 수집기로. macOS/Linux 지원과 ActivityWatch는 뺐다 (2026-10-28).
- AI는 **내 PC의 로컬 모델**만 쓴다 (llama.cpp + Qwen3.5, 외부 전송 없음, `ai_client.Model` 구현).
  사내 AI 서버 연결 기능은 2026-11-04에 뺐다. 로컬 모델 파일은 `llm/`(git 제외), 릴리스에는 앱 zip과 따로 조각으로 올림.
  모델을 고르기 전(=동의 전)에는 AI 꺼짐.
- Claude Code(헤드리스)는 소스에 남겨 두되 **개발·품질 비교용**으로만 쓴다 (배포본에는 없음, 2026-11-04 결정).
  Claude Code에 앱을 등록하는 "Claude Code 연결"은 2026-10-27에 없앰.
- 로컬 전용, 배포는 Windows 포터블 zip. 행망용은 `--offline` 빌드: `mcp`와 그 의존성 30여 개를 빼고,
  앱은 `mcp`가 없으면 Claude Code 모델을 목록에서 숨긴다 (`ai_claude.bundled()`, 2026-10-29).
- 실행기는 pythonw로 창 없이 띄운다: 창을 실수로 닫아 기록이 끊기지 않게. 끄는 건 앱 안의 "앱 종료"만 (2026-10-30).
- 저장소와 배포 zip에는 개발 PC에서 나온 것(사용자·경로·실제 프로젝트·기록·데이터 파일)을 넣지 않는다.
  `tests/test_clean.py`와 빌드 전 검사가 막는다 (2026-10-30).
- 문서·릴리스 설명에는 범위를 `~`로 쓰지 않는다: GitHub이 `1~2분, 5~10분`의 사이를 취소선으로 그린다. "1–2분"(en dash)처럼 쓰고,
  `tests/test_markdown.py`가 추적되는 .md를 검사한다 (2026-11-12).
- 배포: 릴리스 하나에 앱 zip(약 45MB)과 모델(4B·9B, 각각 1.9GB 조각)을 따로 올리고, `WorkHistory-setup.cmd`가
  Windows 기본 기능만으로 앱을 풀고 받은 모델을 합쳐 SHA-256을 검사해 넣는다. 모델은 고른 것만 받고,
  업데이트는 앱 zip만 받아 같은 setup으로 `C:\WorkHistory`를 덮는다(모델 유지). 파일당 2GB 제한, git에는
  넣지 않음. 인터넷용 zip은 배포하지 않는다 (2026-10-30, 앱·모델 분리는 2026-11-05).
- 탭은 대시보드·타임라인·보고서·검색·설정 5개 (대시보드는 2026-11-10에 추가, 첫 화면). 템플릿 일일 리뷰와 이어서 하기 탭은 AI 업무일지·"AI에게 묻기"와 겹쳐 없앴고
  (`daily_reviews`는 v12에서 삭제), 작업 폴더는 설정 탭으로 옮겼다 (2026-11-05).
- 대시보드는 프로젝트를 쓰지 않는다 (2026-11-10): "한 일"은 작업 폴더별 시간(그 밖은 웹·소통·기타)과 작업 폴더별
  파일 변경으로 보여 준다. 활동 분류(개발·문서·소통·웹 등)는 앱 이름 규칙으로 추정하고 화면에 "자동 추정"이라고 표시한다.
- 타임라인에서 프로젝트별 활동 시간, 프로젝트 필터·지정, "미분류" 표시, 하루·세션 메모를 뺐다 (2026-11-05).
  API·DB는 그대로라 이미 있는 메모는 AI 보고서에 계속 쓰이지만, 화면에서 새로 쓸 곳은 없다.
- AI 보고서는 프로젝트와 메모를 쓰지 않는다 (2026-11-05): 프로젝트 이름·다음 할 일(P)·메모(N)를 보내지 않고,
  AI가 이슈 번호·MR·작업 폴더·주제로 업무를 직접 묶어 이름 짓는다. 빠진 일 검사는 프로젝트 대신 작업 폴더 기준.
- 타임라인은 앱별 보기 하나만 둔다 (2026-11-10): 사용자가 앱을 조작할 일을 줄이려고 세션별 보기를 뺐다.
- 세션을 없애고 작업 폴더별 하루 기록으로 바꿨다 (2026-11-10): 시간을 덩어리로 자르지 않고, 창마다 작업 폴더를
  붙여(창의 경로가 작업 폴더 밑에 있을 때만: 제목의 파일이 작업 폴더 안의 파일이거나 제목에 작업 폴더 경로가 있을 때,
  폴더 이름·상대 경로는 인정하지 않음) 같은 폴더끼리 하루 단위로 더한다.
  폴더를 모르는 창은 앞뒤 일에 붙이지 않고 앱 종류로 웹(브라우저)·소통(메신저·메일)·기타로 둔다. 기록은 필요할 때
