## 보완할 점 (지금 못 하고 있는 것)
1. **실제 데이터로 시연하지 못한다.** 시연이 전부 가상 데모다.
2. **실측치와 추정치를 분리하지 않는다.** 측정 날짜도 적어야 한다.
3. **결과물을 바로 업무에 쓰기 어렵다.** 회사 양식으로 바로 나가지 않는다.
4. **"AI가 틀릴 때 어떻게 막는가"를 한눈에 보여 주지 못한다.** (답 거부, 코드 검사, 사실/AI 문장 구분)
5. **AI가 외부로 나간다.** (Claude Code 필요, 로컬 LLM 없음)
6. **발표 준비가 없다.** 대본, 시간 배분, 자막 있는 짧은 영상, 예상 질문.

## 냉정한 자기 평가 (현재 상태 기준)

| 기준 | 점수 (5점) | 이유 |
|---|---|---|
| 실용성 | **2** | 실사용 데이터 없음. 시연이 전부 가상 데모. "시간이 줄었다"는 근거 없음. ActivityWatch + Claude Code + 폴더 등록까지 준비가 많다 |
| 창의성 | **3** | 시간 기록 + AI 보고서는 흔한 범주(WakaTime, Toggl, Rewind). 차별점(파일 변경이 근거, 인용 검증, Claude Code가 내 기록을 MCP로 읽음)은 진짜지만 아직 한 문장으로 전달되지 않는다 |
| 완성도 | **4** | 테스트 203개(10-21), 보안 리뷰 수정, 보고서 평가 8/8, 포터블 패키지. 기술 완성도는 높다 |
| 확장성 | **3** | 모델 교체 구조는 있다. 하지만 폐쇄망에서는 AI가 안 된다(Claude Code 필요). 개인용이라 팀·회사 단위 가치가 보이지 않는다 |
| 보안 | **4** | 로컬 전용, 동의 후 전송, 마스킹, 리뷰와 수정 완료. 다만 외부 AI 전송 자체가 불리하다. 창 제목 기록은 "감시 앱"으로 보일 위험이 있다 |

기술은 탄탄한데 "진짜 써 봤다"는 증거와 바로 쓸 수 있는 결과물, 발표 자료가 없다.
지금 상태로 발표하면 "잘 만든 데모"로 끝난다.

## 개선 제안 (우선순위)

### 반드시 (발표 전)
1. **실사용 2주 데이터 확보.** 오늘 앱을 켜고 작업 폴더 등록. 주간보고를 직접 쓸 때와
   AI 초안을 고칠 때 걸린 시간을 **실측**(날짜 표기). 이게 없으면 실용성 점수가 오르지 않는다.
2. **회사 주간보고 양식으로 내보내기.** 지금은 클립보드 복사뿐. 실제 회사 양식(HWP/엑셀/메일 본문)으로
   바로 붙여 넣을 수 있어야 "바로 쓰는 결과물"이 된다. (양식은 사용자가 제공)
3. **근거 따라가기 한 번에.** 보고서 문장의 [C12] 칩을 누르면 지금은 그날 타임라인으로만 간다.
   → 바로 해당 파일 diff가 펼쳐지게. "이 문장은 어디서 왔을까요? → 실제 diff" 장면이 우리 핵심 차별점.
4. **AI 문장과 근거를 시각적으로 구분.** 사실(파일 변경·메모)과 AI 서술을 색으로 나눈다.

### 하면 좋음
5. **"모르면 멈춘다" 시연.** 기록에 없는 질문에 "기록에서 찾지 못했습니다"라고 답하는 장면.
   보고서에서 걸러 낸 근거 없는 문장 수를 숫자로 보여 준다.
6. **"ChatGPT vs 우리" 비교.** "어제 GOV-1418 어디까지 했지?"를 일반 AI는 모르고, Claude Code + 우리 MCP는
   [C12] 근거와 함께 답한다. 3분 안에 가장 강한 장면.
7. **평가 확대.** 가상 4케이스 → 본인 실데이터 1~2주로 "사람이 고친 문장 수 / 전체" 측정.

### 발표 자료
- 실측/추정 분리, ●◐○ 비교표(수기 일지·git log·WakaTime·ActivityWatch vs 우리),
  원칙 한 장("내 PC에만, 동의 후 전송, 비밀값 가림"), 한계 한 장, 예상 질문.
- 영상은 15~30초짜리 자막 클립 여러 개, AI가 실제로 켜진 상태로 녹화.
- 예상 질문 대비:
  - "폐쇄망에서는?" → `ai_client.Model`로 로컬 LLM 교체 가능하지만 미구현이라고 솔직하게 말한다.
  - "회사가 감시하는 거 아니냐?" → 데이터는 본인 PC에만 있고 회사로 가지 않는다.
