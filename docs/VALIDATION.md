# 실사용 검증 (Phase 4)

## 해커톤 효과 (발표용 숫자)

앱 안의 효과 측정(10-28 ~ 11-04, 보고서 작성 시간·AI 초안을 그대로 쓴 줄·검색 후 여는 시간)은
1주·1명이라 의미 있는 숫자가 나오지 않았고, 시연에 필요 없는 화면이라 11-04에 뺐다.
발표에서는 실측과 경험치를 나눠 밝힌다.

| 항목 | 값 | 근거 |
|---|---|---|
| 주간보고 기억으로 쓰기 | 15~20분, 한 일을 빠뜨리기도 함 | 경험치 |
| AI 초안 만들기 | 약 7분 (기다리지 않고 다른 일을 하다 가져옴) | **실측**: 행망 업무 PC, 인터넷 없이, 내 PC AI |
| AI 초안 검토·수정 | 약 5분 | 경험치 |
| 사람이 쓰는 시간 | 15~20분 → 약 5분 | 위 값으로 계산, 1명 기준 |

숫자보다 큰 가치: 보고서 문장마다 "무슨 일을 어디(파일·창)에서 했는지" 근거가 붙어 눌러 확인된다.

목표: 일주일 동안 실제로 써 보고, 이 앱이 단순 활동 추적기보다 쓸모 있는지 판단한다.
기능 추가보다 관찰이 먼저다.

## 준비

- 창 기록: 앱이 직접 기록한다. 앱이 켜져 있어야 기록된다.
- 앱: 바탕화면의 **작업 기록** 바로가기. 이미 실행 중이면 브라우저만 다시 연다.
  앱은 창 없이 뒤에서 돈다. 끌 때만 개인정보 → 실행 → "앱 종료". 자동 실행은 켜 둔다.
  앱이 꺼져 있던 시간은 창 기록이 비므로, 측정 결과를 말할 때 그런 시간이 있었는지 함께 밝힌다.
- 처음 할 일:
  1. **개인정보 → 기록 대상**에서 "최근 7일 동안 쓴 앱에서 고르기"로 업무 앱을 추가하고
     "업무 앱만 기록"을 켠 뒤 "최근 30일 기록에 다시 적용"
     (브라우저는 앱 대신 창 제목 키워드로: 예 `chrome` + `jira`)
  2. **프로젝트** 탭에서 실제 프로젝트와 키워드 규칙 2~3개 만들기
  3. 상위 폴더 하나만 등록했다면 **작업 폴더**의 "하위 폴더별로 정하기"에서 추천을 확인한다
     (이름이 같은 프로젝트가 미리 골라져 있다. 확인을 눌러야 저장된다)

## 수치 확인

```bash
python -m workhistory.stats --days 7
```

| 지표 | 의미 | 기준 (잠정) |
|---|---|---|
| 분류율 | 업무 시간(업무 외 제외) 중 프로젝트로 분류된 비율 | 70% 미만이면 규칙 보완 |
| 업무 외 | 기록 대상이 아닌 앱에서 보낸 시간 | 업무인데 업무 외로 잡힌다면 기록 대상 규칙 추가 후 다시 적용 |
| 제목 수정 | 자동 제목을 고친 세션 비율 | 50% 넘으면 자동 제목 방식 재검토 |
| 병합·분할 | 범위를 고친 세션 비율 | 20% 넘으면 세션 기준값 조정 (병합이 많으면 너무 잘게, 분할이 많으면 너무 크게 묶는 것) |
| 프로젝트 수정 | 세션 프로젝트를 직접 바꾼 비율 | 높으면 규칙 키워드 추가 |

## 일주일 후 판단 (PRODUCT.md의 질문)

1. 타임라인이 실제 활동을 정확히 반영했나?
2. 세션 묶음 단위가 쓸 만했나? (창 전환마다 쪼개지거나, 너무 뭉치지 않았나)
3. 일일 리뷰가 기억에 의존해 쓰는 것보다 시간을 줄였나?
4. 검색이나 "이어서 하기"로 잊었던 작업을 되찾은 적이 있나?
5. 단순 활동 추적기(앱별 사용 시간)보다 나은 점이 있었나?

결과에 따라 다음 단계를 정한다: 기준값 조정, 자동 제목 개선, 또는 이 범위에서
멈추기. 구독·계정·클라우드·AI 요약은 이 판단 전에는 추가하지 않는다.
