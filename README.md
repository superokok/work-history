# 작업 기록 (WorkHistory)

개발자를 위한 Windows용 로컬 전용 업무 기록 앱입니다. 앱이 직접 기록한 앱/창/유휴 활동과
작업 폴더의 파일 변경을 모아, 검색하고 고칠 수 있는 타임라인으로 만들어 줍니다. 프로젝트와
메모도 함께 관리하고, 내 PC에서 도는 AI로 업무일지·주간보고 초안을 근거와 함께 만듭니다.
데이터는 컴퓨터 밖으로 나가지 않습니다.

문서: [프로젝트 구조](docs/PROJECT_STRUCTURE.md) · [제품](docs/PRODUCT.md) ·
[아키텍처](docs/ARCHITECTURE.md) · [개인정보](docs/PRIVACY.md) · [AI](docs/AI.md) ·

## 받을 파일

| 파일 | 내용 | 이런 PC에 |
|---|---|---|
| `WorkHistory-<버전>-windows-x64-offline-local-ai.zip` (약 8.5GB) | 앱 + 내 PC AI 모델 2개 (Qwen3.5 4B·9B). Claude Code 연결은 뺌 | **행망·폐쇄망**, 인터넷 없이 AI까지 쓰려는 PC |
| `WorkHistory-<버전>-windows-x64.zip` (약 54MB) | 앱만. Claude Code 연결 포함, 모델 없음 | 인터넷이 되는 PC (모델은 따로 `llm\models`에 넣음) |

둘 다 Python 런타임과 AI 실행에 필요한 Microsoft C++ 런타임이 들어 있어, 아무것도 설치되지 않은
인터넷 없는 Windows 10/11에서도 그대로 돌아가고 시스템에 아무것도 설치하지 않습니다. 8.5GB zip은 파일 하나가
4GB를 넘으니 옮길 때 exFAT·NTFS USB를 쓰세요.

## 설치와 처음 설정

1. **`C:\WorkHistory`에 풉니다.** zip을 오른쪽 클릭 → "압축 풀기" → 대상 폴더에 `C:\`만 입력하면
   zip 안의 `WorkHistory` 폴더가 그대로 `C:\WorkHistory`가 됩니다. zip 파일 자체는 어디에 있어도 됩니다.
   - 피할 곳: 깊은 폴더(경로 260자 제한), OneDrive와 동기화되는 바탕화면·문서(8.5GB가 업로드됨),
     네트워크 드라이브·USB, `C:\Program Files`(관리자 권한 필요).
   - zip을 탐색기에서 열기만 한 채 안의 파일을 실행하지 말고, 반드시 다 푼 뒤 실행합니다.
   - 풀린 폴더는 그 자리에 둡니다 (자동 실행과 바로가기가 그 폴더를 가리킵니다).
2. **`C:\WorkHistory\작업 기록.cmd`** 를 더블클릭합니다. 검은 창이 잠깐 떴다 사라지고 브라우저에 앱이 열립니다.
3. 앱 안에서 한 번만 설정합니다 (터미널 작업은 필요 없습니다).
   - **개인정보 → 실행**: "컴퓨터를 켤 때 자동 실행" 켜기, "바탕화면 바로가기 만들기"
   - **프로젝트 → 작업 폴더**: 결과물을 만드는 폴더 등록. 상위 폴더 하나만 등록했다면
     "하위 폴더별로 정하기"에서 각 폴더의 프로젝트를 확인합니다.
   - **프로젝트**: 실제 프로젝트와 키워드 규칙 2~3개
   - **개인정보 → 기록 대상**: 하루쯤 쓴 뒤 "최근 7일 동안 쓴 앱에서 고르기"로 업무 앱을 고르고
     "업무 앱만 기록"을 켭니다 (나머지 앱은 이름·제목 없이 "업무 외" 시간으로만 남음).
   - **개인정보 → AI 설정**: 모델을 고르면 AI가 켜집니다 (아래 "AI").

새로 설치하면 아무것도 등록되어 있지 않은 빈 상태로 시작합니다. 창 기록은 앱을 켜는 순간부터
따로 설정하지 않아도 남습니다.

## 매일 쓰기

- **열기**: 바탕화면의 **작업 기록** 바로가기 (또는 `작업 기록.cmd`). 이미 켜져 있으면 그 앱을 엽니다.
- **앱은 창 없이 뒤에서** 기록합니다. 브라우저를 닫아도 기록은 계속됩니다. 작업 표시줄에
  아무 창도 없는 것이 정상입니다.
- **끄기**: 개인정보 → 실행 → **앱 종료**. 꺼져 있는 동안은 창 기록이 남지 않습니다
  (작업 폴더의 파일 변경은 다시 켜면 따라잡습니다). 자동 실행을 켜 두세요.
- **주소**: 보통 `http://127.0.0.1:5730/`. 다른 프로그램이 5730을 쓰고 있으면 5731~5739 중
  빈 포트로 자동으로 켜지고, 실제 주소는 개인정보 → 실행에 표시됩니다. 바로가기로 여는 것이
  가장 확실합니다.

## 업데이트

앱을 끄고(앱 종료), 새 zip을 풀어 앱 폴더를 통째로 바꾼 뒤 다시 켭니다. 기록과 설정은 앱 폴더가
아니라 `%LOCALAPPDATA%\WorkHistory`에 있어서 그대로 이어집니다. 같은 위치에 풀면 바로가기도
그대로 쓸 수 있습니다.

## 사용법

- **타임라인**: 창 활동에서 추정한 **작업 세션**으로 하루를 보여 줍니다. 유휴(AFK)와
  화면 잠금 시간은 빠집니다. 세션마다 이름 바꾸기(비우면 자동 제목으로 돌아감),
  프로젝트 지정, 메모, 합계에서 제외, 다음 세션과 병합, 창 기록을 펼쳐 원하는 줄에서
  분할을 할 수 있습니다. 이름을 바꾸거나 메모를 단 세션도 계속 작업하면 이어서
  늘어납니다. 하루 메모와 그날의 파일 변경(누르면 diff)은 오른쪽에 나옵니다.
- **리뷰**: 세션과 메모로 만든 일일 리뷰 초안을 고쳐 쓸 수 있습니다 (AI 아님). 섹션은
  [자동 집계] / [자동 추정] / [직접 작성]으로 표시됩니다. 고친 뒤 저장하면 검색됩니다.
- **보고서**: 업무일지·주간보고 AI 초안. 문장마다 근거(세션·파일 변경·메모)가 칩으로 붙고,
  누르면 그 기록으로 갑니다. 근거 없는 "완료" 같은 문장은 표시됩니다. 아래 "효과 측정"
  카드에 보고서 작성 시간 등이 숫자로만 쌓입니다.
- **이어서 하기**: 최근 작업 순으로 프로젝트를 보여 줍니다. 프로젝트마다 다음 할 일,
  마지막 세션과 거기서 본 마지막 창, 최근 세션, 이전 메모가 나옵니다.
- **검색**: 세션, 창 제목, 앱 이름, 메모, 리뷰, 프로젝트, 파일 변경을 검색하며
  날짜와 프로젝트로 거를 수 있습니다. 위쪽 **AI에게 묻기**에는 "지난주 ○○ 어디까지 했지?"
  같은 질문을 하면 근거와 함께 답합니다.
- **프로젝트**: **작업 폴더**(결과물 기록: 등록한 폴더의 바뀐 파일을 5분마다 숨김 로컬 Git
  저장소에 스냅샷합니다. 원래 폴더나 그 안의 .git은 건드리지 않고, 비밀값과 빌드 결과물은
  건너뜁니다), 프로젝트, 키워드 규칙(앱 이름이나 창 제목에 키워드가 들어 있으면 해당
  프로젝트로, 대소문자 무시, 가장 긴 키워드 우선).
- **개인정보**: 실행(자동 실행, 바로가기, 앱 종료, 주소), AI 설정, 기록 범위(모든 앱 또는
  업무 앱만), 제외 목록, 일시 정지/재개, 기간 또는 전체 삭제.

세션 묶기 규칙과 기준값은 [ARCHITECTURE §6](docs/ARCHITECTURE.md)에 있습니다.

## AI (선택)

보고서와 "AI에게 묻기"는 **개인정보 → AI 설정**에서 고른 모델을 씁니다. 모델을 고르기 전에는
AI가 꺼져 있고 실제 업무 기록은 어디에도 보내지 않습니다 (고르는 것이 동의입니다).

- **내 PC · <모델>** (추천): 앱 폴더 `llm\models`의 모델을 이 PC에서 직접 돌립니다
  (llama.cpp + Qwen3.5). 기록이 PC 밖으로 나가지 않고 인터넷이 없어도 됩니다. 폴더에
  `.gguf` 파일을 넣으면 자동으로 목록에 나타납니다.
  - **9B**를 권합니다. 4B는 더 빠르지만 끝나지 않은 일을 "완료"라고 쓰는 경우가 있었습니다.
  - 속도(12세대 Core i5 노트북 기준): 일일 보고서 1~2분, 주간보고 3~10분. 그래픽 메모리가
    4GB 미만인 그래픽카드는 CPU만 쓸 때와 비슷합니다. 측정: [docs/AI.md](docs/AI.md).
- **AI 서버 · <이름>**: 행망·사내 LLM 서버를 주소(`http://IP:포트`), 모델 이름, API 키(선택)로
  등록해서 씁니다. OpenAI 호환 API면 됩니다 (vLLM, Ollama, llama.cpp, LM Studio 등). 고르면
  기록이 (비밀값을 가린 뒤) 그 서버로 갑니다.
- **Claude Code · Sonnet 등** (인터넷용 zip에만): 이 PC에 설치되어 로그인된 Claude Code를
  헤드리스로 씁니다 (빠름, API 키 불필요, 사용량은 본인 계정). 기록이 비밀값을 가린 뒤
  Anthropic으로 전송됩니다. 앱의 읽기 전용 기록 도구 외에 모든 도구를 끄고 실행합니다.

"보낼 내용 보기"는 보고서에 쓰일 내용을 그대로 보여 주고, "연결 확인"은 업무 기록 없이
동작만 확인합니다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| 앱이 켜져 있는지 모르겠음 | 바탕화면 바로가기를 누르세요. 켜져 있으면 그 앱이 열리고, 꺼져 있으면 켭니다. |
| 시작할 때 오류 메시지 상자 | 내용대로 조치하세요. 자세한 기록은 `%LOCALAPPDATA%\WorkHistory\workhistory.log`에 있습니다 (기록 내용은 들어 있지 않음). |
| "포트 5730~5739를 모두 다른 프로그램이 쓰고 있어…" | 열 개 포트가 모두 막힌 드문 경우입니다. 쓰지 않는 프로그램을 끄고 다시 실행하세요. |
| "창 기록 오류" | 상태 칩에 마우스를 올리면 원인이 보입니다. 앱을 다시 시작해 보세요. 그동안 저장된 기록은 계속 보입니다. |
| 유휴 데이터가 없다는 노란 경고 | 그날 AFK 데이터가 없어 창 시간이 모두 활동 시간으로 잡혔고, 실제보다 많을 수 있습니다. |
| 일부 창이 `unknown`으로 나옴 | 보호된 시스템 프로세스는 앱 이름을 읽을 수 없습니다. 화면 잠금·유휴 중에 주로 생깁니다. |
| AI 초안이 아주 느림 | 그래픽카드가 없거나 약한 PC입니다. 기다리는 동안 다른 일을 하거나 4B를 써 보세요 (품질은 9B가 낫습니다). |
| 압축 해제 시 "경로가 너무 깁니다" | 더 짧은 폴더(예: `C:\WorkHistory`)에 풀어 주세요. |
| "작업 기록.cmd" 실행 전에 Windows 경고 (내려받은 파일) | 압축 풀기 전에 zip을 오른쪽 클릭 → 속성 → 차단 해제하거나, "실행"을 고르세요. 회사 보안 프로그램이 `python.exe`·`llama-server.exe`를 막으면 예외 등록이 필요합니다. |
| 꺼 둔 동안의 창 기록이 없음 | 창 활동은 앱이 켜져 있을 때만 기록합니다. 파일 변경은 다음 스캔 때 따라잡습니다. |

## 개발

```bash
uv venv .venv --python 3.12
uv pip install --python .venv/Scripts/python.exe -e .[claude]
```

소스에서 실행: `start-workhistory.cmd`(`.venv`를 우선 사용, 창 없이 실행) 또는 콘솔에 로그를
보려면 `.venv/Scripts/python.exe -m workhistory`. 런타임 패키지는 `dulwich`(폴더 스냅샷,
Apache-2.0)와 `mcp`(MIT, Claude Code용)와 그 의존성뿐이며 모두 상업적 사용이 가능합니다
([THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)).

**배포 zip 빌드** (venv의 Python과 패키지를 복사하며 아무것도 내려받지 않습니다):

```bash
python tools/build_portable.py                          # 인터넷용, 모델 없음
python tools/build_portable.py --offline --with-models  # 행망용, 모델 포함
```

`--with-models`는 `llm/models`의 모델까지 넣고, `--offline`은 Claude Code 연결(`mcp`와 의존성
30여 개)을 뺍니다. 빌드는 압축하기 전에 번들 Python만으로 앱을 import해 보고, 개발 PC의
흔적(사용자 이름·경로·git 계정·데이터 파일)이 없는지 검사해서 있으면 멈춥니다.

**저장소와 zip은 다른 사람에게 보여 주는 것**이라 개발 PC에서 나온 것(실제 기록, 경로, 계정,
프로젝트 이름 등)을 넣지 않습니다. `tests/test_clean.py`가 추적 파일 전체를 검사합니다.

### 명령행 옵션

실행기는 받은 인수를 앱에 그대로 넘깁니다.

| 옵션 | 의미 |
|---|---|
| `--port N` | 이 포트만 사용 (기본: 5730부터 5739까지 빈 포트, 항상 127.0.0.1에만 바인딩) |
| `--db PATH` | 데이터베이스 파일 (기본: `%LOCALAPPDATA%\WorkHistory\workhistory.db`) |
| `--demo` | 가상의 2주 개발자 시나리오가 담긴 별도 `demo.db` (데모로 표시됨), 기록 안 함 |
| `--window` | `pywebview`가 설치되어 있으면 자체 창, 없으면 브라우저. 아직 검증 안 됨. |
| `--no-browser` | 브라우저를 열지 않음 (자동 실행이 씀) |
| `--verbose` | 디버그 로그 |

### 테스트와 통계

```bash
.venv/Scripts/python.exe -m unittest discover -s tests -t .
python -m workhistory.stats --days 7     # 날짜별 보정률 (이름 변경·프로젝트 재지정·병합·분할·제외)
```

테스트는 임시 데이터베이스와 가짜 창 읽기를 씁니다 (실제 Windows 창을 읽는 테스트 하나 포함).
